# Как запустить и показать Lab 3

## 1. Открой готовую ветку

Используй ветку `CSS-3008-lab3-jdbc`. В `main` эта работа появится только после слияния PR.

Скачай ZIP этой ветки или выполни:

```powershell
git clone --branch CSS-3008-lab3-jdbc https://github.com/argymakmyrzaliyev-star/purchase-tracker.git
cd purchase-tracker
```

В Windows можно открыть папку с `pom.xml`, написать `powershell` в адресной строке Проводника и нажать Enter.

## 2. Проверь программы

```powershell
java -version
mvn -version
docker compose version
```

Нужны Java 21, Maven 3.9+ и запущенный Docker Desktop. В выводе Maven тоже должна быть Java 21. Вместо Docker можно использовать локальный PostgreSQL с базой `css` и пользователем/паролем `css`.

## 3. Запусти PostgreSQL

```powershell
docker compose up -d --wait
```

Compose запускает только PostgreSQL. Приложение Java работает отдельно.

## 4. Покажи SQL и откат в psql

```powershell
docker compose exec -T postgres psql -U css -d css -v ON_ERROR_STOP=1 -f /lab/schema.sql
docker compose exec -T postgres psql -U css -d css -f /demo/rollback-demo.sql
```

Во втором скрипте ошибка duplicate key ожидаемая: он специально вставляет одинаковый номер дважды в одной транзакции. Далее выполняется ROLLBACK, количество записей становится 0. Последняя строка:

```text
PSQL ROLLBACK PASSED: SQLSTATE 23505; count = 0
```

## 5. Покажи тесты

```powershell
mvn -q verify
```

Команда должна завершиться без ошибок. Для подробного вывода можно использовать `mvn verify`; в конце будет `BUILD SUCCESS`.

Тесты создают чистую таблицу в схеме `purchase_tracker_lab3_test`. Таблица приложения в схеме `public` сохраняется.

## 6. Покажи два сценария в приложении

```powershell
mvn spring-boot:run "-Dspring-boot.run.profiles=demo"
```

Дождись:

```text
ROLLBACK count = 0
COMMITTED count = 1
LAB 3 DEMO PASSED
```

В первом случае обе вставки были внутри одной транзакции, поэтому ошибка второй отменила первую. Во втором случае первый вызов уже сохранил заявку; повторный вызов не удаляет её.

Программа завершится сама. Каждый запуск демонстрации сохраняет одну новую примерную заявку с уникальным номером.

## 7. Посмотри сохранённую заявку

```powershell
docker compose exec -T postgres psql -U css -d css -c "SELECT business_key, status, title FROM purchase_request ORDER BY created_at DESC LIMIT 5;"
```

В результате будет заявка со статусом DRAFT. Бизнес-ключ начинается с `PR-COMMITTED-`.

## Что объяснить на защите

«Мы продолжили Purchase Tracker и добавили PostgreSQL. У заявки два идентификатора: внутренний UUID и понятный человеку уникальный номер. Схему таблицы написали вручную. Ограничение CHECK разрешает только DRAFT, APPROVED и ORDERED.

Сервис вызывает репозиторий через интерфейс. Репозиторий работает через JdbcTemplate и подставляет значения параметрами. Повторный ключ превращается в наше исключение DuplicatePurchase.

Мы проверили две ситуации. Если в одной транзакции вторая вставка падает, откатываются обе — остаётся ноль записей. Если первая регистрация уже завершилась, повторная регистрация откатывает только свою транзакцию — первая запись остаётся.

Доменные классы не зависят от Spring и JDBC. Тесты проверяют настоящую PostgreSQL, а внешний интерфейс репозитория в отдельном модульном тесте заменён mock-объектом».

## Короткие ответы

| Вопрос | Ответ |
| --- | --- |
| Зачем два идентификатора? | UUID — стабильный внутренний ключ; PR-19 — номер для человека. |
| Зачем UNIQUE и NOT NULL вместе? | Номер должен быть уникальным и обязательно заполненным. Пустые строки дополнительно отклоняет Java. |
| Что такое JDBC? | Способ выполнять SQL и получать результаты из Java. |
| Что такое JdbcTemplate? | Средство Spring, которое упрощает JDBC и работу с ресурсами. |
| Зачем вопросительные знаки в SQL? | Значения передаются отдельно от SQL-команды и остаются данными. |
| Почему исключение unchecked? | По умолчанию Spring откатывает транзакцию при выходе с RuntimeException. |
| Где стоит @Transactional? | На методах сервиса; доменная политика остаётся обычным Java-классом. |
| Почему на тестах нет @Transactional? | Чтобы проверить результат после настоящего завершения транзакции сервиса. |
| Что такое mock? | Подмена внешнего интерфейса для проверки сервиса без обращения к реальной базе. |
| Почему ошибка duplicate key в psql нормальна? | Мы намеренно вызываем её, затем проверяем откат и count = 0. |

## Если что-то не запускается

- `mvn` не найден: Maven не установлен или его `bin` отсутствует в PATH.
- `release version 21 not supported`: Maven использует старую Java; проверь `mvn -version` и JAVA_HOME.
- Docker не отвечает: открой Docker Desktop и дождись запуска.
- Порт 5432 занят: на компьютере уже работает PostgreSQL или другой контейнер; используй существующую базу либо настрой свободный порт и DB_URL.
- `Connection refused`: проверь `docker compose ps` и запуск PostgreSQL.
- `password authentication failed`: проверь учётные данные и ранее созданный том базы. Изменение Compose не меняет пароль уже существующей базы.

После показа останови базу, сохранив данные:

```powershell
docker compose stop
```
